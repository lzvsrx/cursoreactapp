## Alterações realizadas

- Adicionado o desafio Bat-Sinal com ativação, formulário validado, confirmação e documentação.
- Alinhados os apps às correções disponíveis do Expo SDK 57: Expo `57.0.31`, Metro Runtime `57.0.17`, Splash Screen `57.0.10` e, no portfólio, Asset `57.0.20` e Sharing `57.0.24`.
- Adicionados os scripts de exportação que faltavam em Expo Events.
- Atualizado `undici` de `8.11.2` para `8.12.3` nos sites; a auditoria web ficou sem alertas.
- Substituída a geração de senhas com `Math.random` por `expo-crypto`, com 16 caracteres e amostragem sem viés de módulo, nos dois conjuntos de componentes herdados do Bat Pass.
- Bloqueada a cópia de senha vazia e adicionadas mensagens para sucesso/falha de geração e cópia.
- Melhorados o tamanho adaptável do símbolo, rótulo de acessibilidade, indicação de estado e barra de status do Lanterna Verde. Esse exercício alterna a interface; não aciona o flash físico do aparelho.
- Corrigido o tratamento de JSON inválido, arquivos nulos, caminhos não permitidos, duplicatas e excesso de dados na API de sincronização das duas versões web. Falhas do serviço externo não devolvem detalhes internos ao cliente.
- Incluída a pasta `api` no TypeScript dos sites, com tipos e imports de Node explícitos.
- Adicionados testes da API, rotina de verificação local, workflow de CI e ferramenta de backup com hashes SHA-256.
- Atualizados os READMEs e o índice de projetos.

Os catálogos de certificados foram confrontados com os arquivos locais: 142 em `lzdev` e 146 em `portfolio-lzdev/web`, sem arquivos ausentes.

## Alertas que permanecem

Cada app Expo apresenta cinco entradas altas de auditoria relacionadas às cadeias de dependência de `@expo/cli`, `@expo/code-signing-certificates`, `expo`, `node-forge` e `zod`. Elas decorrem de dois avisos subjacentes nas ferramentas do Expo:

- [node-forge: verificação de assinatura RSA](https://github.com/advisories/GHSA-86w9-cpqp-85rv). A versão mais recente encontrada nesta revisão foi `1.4.0`, ainda incluída no intervalo afetado.
- [Zod: consumo excessivo de memória](https://github.com/advisories/GHSA-mrhx-c7xc-m3w5). A correção indicada é da série 4, enquanto a CLI instalada depende da série 3.

Não foi aplicado `npm audit fix --force`: a resolução sugerida incluía regressão para Expo 44. Os alertas permanecem registrados, não são considerados resolvidos e devem ser acompanhados junto às atualizações oficiais do Expo. O CI informa auditorias sem mascarar falhas de build ou teste.

## Atualizações e próximos passos

1. **Teste real dos apps:** validar Android e iOS, teclado e rolagem do Bat-Sinal, geração/cópia de senha e abertura/compartilhamento de certificados. Não foram compilados APKs/IPAs nem executados em aparelhos nesta revisão.
2. **Autenticação do painel:** o login atual é local e não constitui proteção de servidor. Para uso administrativo de produção, implementar sessão autenticada e autorização no backend. A API de sincronização depende de segredo e token configurados no servidor.
3. **Teste da sincronização em homologação:** testar o endpoint implantado com um repositório de teste, validar permissões do token e estudar publicação atômica dos quatro arquivos. A implementação atual os publica sequencialmente e pode concluir apenas parte em caso de falha.
4. **Migração do Expo:** `npm outdated` identificou Expo `58.0.19` e React Native `0.88.0` como versões mais recentes. Essa migração exige revisão conjunta de dependências e testes em dispositivos; não basta atualizar React Native isoladamente. SDK 57, Babel 7 e TypeScript 6 foram mantidos nesta revisão para preservar a matriz validada.
5. **Próxima rodada web:** foram identificadas atualizações compatíveis para React/React DOM `19.3.1`, Vite `8.3.5`, Vitest `5.0.5`, jsdom `30.1.3`, Lucide React `1.61.0`, User Event `14.6.8` e tipos de Node `26.6.5`. Elas não foram aplicadas nesta revisão; o conjunto atual foi validado e não apresenta alertas no `npm audit`. React Native Web `0.21.4` também apareceu como atualização possível para os apps.
6. **Reduzir duplicação:** avaliar compartilhar dados/componentes entre `lzdev` e `portfolio-lzdev/web`, mantendo os destinos de publicação independentes, para evitar correções divergentes.

A tentativa de conferência visual no Chrome foi bloqueada pelo controle do computador, que não conseguiu identificar a URL atual com segurança. Portanto, essa conferência não foi contabilizada como aprovada. Os testes de interface web executados foram os automatizados com Testing Library.

## Publicação e backup

O código, as configurações, os assets e os lockfiles são versionados normalmente. As pastas ignoradas foram destinadas a arquivos compactados por projeto na Release `revisao-2026-10-25`, incluindo `node_modules`, builds e caches do Expo, conforme solicitado. O manifesto da Release lista os caminhos incluídos, tamanho e SHA-256 de cada arquivo. Os arquivos são lidos novamente pelo `tar` antes do envio para verificar a integridade.

Os backups de dependências refletem o ambiente Windows desta revisão. Em outro sistema ou para uma instalação limpa, prefira `npm ci`. A pasta `dist` de cada app corresponde à última plataforma exportada, pois os scripts usam o diretório padrão do Expo; execute uma nova exportação para a plataforma desejada.
